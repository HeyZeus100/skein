# Encrypted application integration candidate

`skein-gg11.32.3` adds three ordinary app instrumentation cases in `ContextualSendPathInstrumentedTest`. Each opens an independent synthetic cache vault through `DeviceVaultOpener`, ingests a newly created note with the application's real `IngestPipelines` (chunker, FTS and source revisions), creates/binds its real default Space, and sends through the real `ChatTurnController` → `SendPipeline` → `RetrievalServiceImpl` chain. The test does not construct follow-up requests or source pins. A random test-only key and deterministic scripted inference are the only synthetic ports.

1. `persisted_citation_resolves_raw_followup_through_encrypted_send_path` checks the canonical persisted citation, current source revision, raw follow-up query, absence of assistant prose in recall, original scores, saved follow-up citation and unchanged preceding messages.
2. `edited_and_reingested_source_cannot_repin_a_previous_encrypted_turn` replaces the source through the actual repository, drains real ingest, checks the new revision and requires `SOURCE_CHANGED` with no second generation or rewritten earlier quote.
3. `committed_source_deletion_preserves_quotes_and_refuses_contextual_generation` deletes the actual source and requires `SOURCE_UNAVAILABLE`, an uncited application-owned abstention, no second generation and byte-equivalent prior message values.

Each fixture closes its controller/scope and vault session before zeroing its random key and deleting only its own temporary directory. It never launches an Activity, installs a global provider, touches owner files, prompts authentication, loads a model or changes model defaults.

Actual encrypted runtime acceptance requires the ordinary emulator queue and source-attributed XML. Compilation alone does not execute SQLCipher, FTS, ingest or the app send path.
