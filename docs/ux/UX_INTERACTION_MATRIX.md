## Read this first

- **143 controls** after merging 39 controls that two audits reported separately (181 source rows + 1 device-only row).
- **18 DEAD controls, all P0** (checklist at the end). **45 rows are P0** in total; each P0 row names the consolidated finding it belongs to (`UX-P0-nn`).
- The P0 rows cluster in five places: the command bar (the model chip crushes the only input), the drawer and split-view rail (placeholders and no-ops), system Back (leaves the app from everywhere), document opening (every kind opens as a note), and state that dies on fold, tab switch or lock.
- Only **43 of 143 controls fully work**, and 25 of those are in Settings, the vault gate (setup, unlock, restore, reset) and the tab menu. The chat surface has one fully working control: ⏎ Send.

## Legend

**States** (brief §19):

| State | Meaning in this matrix |
|---|---|
| WORKING | Does what a user would expect. May still carry a P1/P2 defect (label, target size). |
| PARTIAL | Does part of the job, or works only in some states (for example only when no tab is open). |
| DEAD | A **visible** control that does nothing. Always P0 (§19). |
| DUPLICATE | Duplicates another navigation path; its defect is recorded in Actual Action. |
| CONFUSING | Works, but what it does is not what it appears to do. |
| FUTURE | Not rendered, absent, or a gesture with nothing visible behind it. Recorded so the redesign knows the gap or the unwired code exists. |
| REMOVE | Should not be in the product as it stands (implementation text, inert placeholder). |

**Severity** follows brief §47: P0 = dead control, broken navigation, crash, data loss, unusable outer screen, reset on fold, inaccessible important screen. `—` = no defect found.

**IDs.** `SH-nn`, `CH-nn` and `KN-nn` are the row numbers in the three source matrices, in source order, so every row can be traced back. `DV-01` is the one control found only by the device pass. `A = B` means two audits reported the same control; the row keeps A's text and folds in B's evidence.

**Sort order.** Severity (P0 first), then surface in product order: shell and navigation → chat → knowledge (notes, editor, graph) → models → settings → vault gate.

**Consolidation decisions** (the editor's, not the source audits'):
- `SH-07 = CH-02` (palette `/chat`) and the unwired `SH-43`/`SH-44` "New chat / New note" buttons are raised to **P0** (`UX-P0-16`): starting a chat has no visible control, and the device shows the palette tap ending in "No matching commands".
- `KN-40` ("Note not found") and `KN-47` (graph entity/tag nodes) were DEAD at P1 in the source; the §19 rule makes them **P0**.
- `CH-12` (long-press to copy), `CH-16 = SH-48` (composer `/`) and `KN-52` (graph for TalkBack) move from DEAD to **FUTURE**: nothing visible is dead; the affordance is missing.
- Where two audits disagreed on severity for the same control, the higher one is kept when the evidence supports it (for example `CH-01 = SH-05`, the model chip, is P0 because the JVM screenshots confirm it collapses the command field).
