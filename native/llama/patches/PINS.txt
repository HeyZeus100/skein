# native/llama/patches — pins for the local patches applied to llama.cpp's
# Vulkan shader sources (bd skein-ylux).
#
# The submodule tree under `third_party/` is NEVER written to. At CMake
# configure time `native/llama/CMakeLists.txt` §5a copies
# `third_party/llama.cpp/ggml/src/ggml-vulkan/vulkan-shaders/` into
# `<cxx build dir>/vulkan-shaders-patched/`, applies each `patch` record
# below to that copy, and points the `glslc` the shader generator invokes at
# a wrapper that redirects reads of the pristine directory to the copy.
#
# Every hash below is checked on every configure, in this order:
#
#   patch  <sha256> <file under native/llama/patches/>
#          the patch file itself, so an edited patch cannot apply silently
#   before <sha256> <file relative to vulkan-shaders/>
#          the PRISTINE upstream file, so a submodule pin bump that touches a
#          patched file fails loudly here instead of applying a stale hunk
#   after  <sha256> <file relative to vulkan-shaders/>
#          the patched result, so the bytes that are compiled are pinned
#          regardless of which `patch(1)` implementation applied them
#
# Any mismatch is a FATAL_ERROR naming the file. Re-pinning is deliberate:
# regenerate the patch against the new upstream file, re-measure determinism
# (tools/rb/so-determinism.sh), and update this file in the same commit.
#
